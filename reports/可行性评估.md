# 用强化学习做象棋程序 —— 本机可行性评估

日期：2026-11-19　机器：KVM 虚拟机 `vm`（4 vCPU / 7.5 GB / 无 GPU）
目录：`/root/rl-chess`（新建）

---

## 0. 结论先行

| 目标 | 本机是否可行 | 说明 |
|---|---|---|
| 跑通 RL 自博弈管线、看得见学习曲线 | ✅ 可行 | 国际象棋有现成正确引擎；4 核实测 5.5 万局面/秒 |
| 从零自博弈练到"业余入门～业余中级"（≈1000–1400 Elo） | ✅ 可行（数天～一周） | 算力比 AlphaZero 少 3 个数量级，棋力天花板就在这里 |
| 从零自博弈练到"能赢俱乐部棋手"（1800+ Elo） | ❌ 不可行 | 需要 GPU 集群级别的自博弈量（AlphaZero: 4400 万局 / 5000 TPU） |
| 训练一个"下得有来有回"的引擎（1600–1900 Elo） | ✅ 可行，但要换路线 | 用 Stockfish / Fairy-Stockfish 蒸馏 + RL 微调，而不是纯从零 |
| 中国象棋（不是国际象棋） | ⚠️ 可行性打折 | 现成 Python 走子库 `cchess` **有正确性 bug**（实测少 5% 合法着法），需先自己重写走子生成（1–2 天） |

一句话：**能做出"有意思"的东西，但要接受"棋力上限由算力决定"这个现实；想棋力强就走蒸馏路线。**

## 2. 实测吞吐（决定训练预算的关键数字）

| 测量项 | 结果 |
|---|---|
| python-chess 走子生成+随机选步 | **13,637 局面/s** 单核；**54,674 局面/s** 4 进程（4.0× 线性扩展） |
| numpy 自写网络（768→256→256→{4096 policy, 1 value}）推理 | bs=1 **6,996 eval/s**；bs=8 **19,915/s**；bs=64 **44,701/s** |
| 同网络训练（前向+反向+SGD，batch 256） | **5,295 样本/s**（约 48 ms/步） |
| 512×512 矩阵乘 | 144.6 GFLOPS（说明 4 核 AVX-512 可用性良好，CPU 不是瓶颈） |
| cchess 中象走子（perft 遍历，含 deepcopy 开销） | **4,781 节点/s** 单核（比 python-chess 慢 2.9 倍） |

### 换算成"每小时多少局自博弈"

每节点成本 ≈ 走子 73 µs + 网络 50 µs（bs=8）+ Python MCTS 开销 40–150 µs ≈ **160–270 µs/节点**
→ 单进程 3.7–6.1k 节点/s，4 进程 **1.3–2.2 万节点/s**
→ 一局 ≈ 100 sims/步 × 80 步 = 8,000 节点
→ 理论 1.6–2.7 局/s，**现实按 5 折估：约 3,000–5,000 局/小时，单日 7–12 万局**

对比 AlphaZero：4400 万局 / 9 小时 / 5000 TPU-v1。我们一周约 50–80 万局，**是它的 1/60～1/100**——所以棋力天花板必须下调，这是物理限制，不是实现问题。

## 3. 两个真实的正确性卡点

### 3.1 中国象棋：`cchess` 走子生成是错的（已用 Fairy-Stockfish 交叉验证）

| perft 深度 | `cchess` 结果 | 权威值（Fairy-Stockfish 实测 / 公开值） | 偏差 |
|---|---|---|---|
| 1 | 44 | 44 | ✅ |
| 2 | 1,843 | 1,920 | **-4.0%** |
| 3 | 75,652 | 79,666 | **-5.0%** |
| 4 | — | 3,290,240（本次用 Fairy-Stockfish 实跑确认） | — |

含义：用它训练 RL，agent 会学到"某些合法着法不存在"，等价于在残缺规则下学习，后期无法与真引擎对局。**必须先修/重写走子生成**。
（另外它每走一步 `copy.deepcopy` 整个棋盘，这也是它只有 4.8k 节点/s 的原因，重写时一并解决。）

### 3.2 无 GPU

意味着：网络只能是"小而窄"的（本文按 ~50 万参数估），且推理走 AVX-512/VNNI；每样本 1.3 MFLOP 的网络在 CPU 上 9 µs 就能算完，瓶颈其实在 Python 的 MCTS 树操作，不在算力。**这点反而对我们有利**：小网络 + 少 sims 时，4 核 CPU 的"每秒局数"并不难看。

## 4. 三条路线（按投入/回报排序）

### 路线 A：迷你 AlphaZero（国际象棋，从零自博弈）—— 推荐做"有意思的 demo"

- 组成：python-chess（规则，已验证） + 自写 MCTS（PUCT） + numpy 小网络（可选 torch）+ 自博弈数据回灌。
- 预算：单日 7–12 万局；一周 50–80 万局；网络 0.3–1 M 参数。
- 预期棋力（**估计，不确定性大**）：3 天 ≈ 800–1000 Elo（刚会走子、懂吃子），1 周 ≈ 1100–1400 Elo（能赢随便下的人，输给受过训练的业余棋手）。
- 工作量：核心 ~400 行 Python，2–3 天出 v1（含可视化：终端棋盘 + Elo/损失曲线 + 每 1000 局对 Stockfish 限时 100 ms 的胜率阶梯）。
- 风险：Python MCTS 树操作会成为真实瓶颈 → 用"批量叶节点评估"（攒 8–32 个叶子一次前向）可把吞吐提 2–3 倍，这是标准做法（KataGo/Leela 都这么做）。

### 路线 B：中国象棋版本（同 A，但先补地基）

- 前置任务：重写中象走子生成（9×10 棋盘、7 种子、飞将/蹩马腿/塞象眼全部覆盖），并用 perft 1/2/3/4 = 44 / 1,920 / 79,666 / 3,290,240 做单测。向量化后目标 3–5 万节点/s（比 cchess 快 6–10 倍）。
- 工作量：走子 + 单测 1–2 天，之后复用路线 A 的全部管线。
- 预期棋力：同等算力下比国际象棋略低（分支因子小但局面更"战术化"），1 周约 1000–1300 Elo（中象 Elo 体系与国象不同，只作量级参考）。
- 好处：中象对你我更有"观赏性"，也更容易找人试玩；坏处：所有基础设施要自己写，且没有现成的权威 Python 参照物（Fairy-Stockfish 只能当裁判/老师，不能当规则库直接用）。

### 路线 C：蒸馏 + RL 微调（想要"棋力"就走这条）

1. 用 Stockfish 17（国象）/ Fairy-Stockfish（中象）在 20–50 万局面上打标签（policy: multipv 前 k 步；value: 评估分转 [-1,1]）。
   - 标注吞吐未实测（成本在 SF 搜索深度），粗估 depth 6–8 单核 200–1000 局面/s → 50 万局面 10–40 分钟单核，4 进程并行再除以 ~3。
2. 监督学习蒸馏进小网络：实测 **5,295 样本/s** → 50 万局面 × 5 epoch = **约 8 分钟**。
3. 用蒸馏网络做 MCTS 先验，再自博弈微调（同路线 A 的循环，但起点高得多）。
- 预期棋力：蒸馏后 100 sims ≈ 1600–1900 Elo；再加一周自博弈微调可到 1900–2100。
- 代价：多花 2–3 天写数据生成/标签管线；学术上不如"从零 AlphaZero"纯粹，但工程上性价比最高。

## 5. 三条路线对比

| | A 迷你 AlphaZero（国象） | B 中国象棋版 | C 蒸馏 + RL |
|---|---|---|---|
| 前置工作量 | 0（库现成） | +1–2 天写走子 | +2–3 天写标注管线 |
| 到 v1 可跑 | 2–3 天 | 4–5 天 | 4–6 天 |
| 一周后棋力（估） | 1100–1400 | 1000–1300 | 1600–1900 |
| 算力压力 | 中（吃满 4 核） | 中高（走子慢） | 中 |
| 主要风险 | MCTS 的 Python 开销 | 走子正确性 | 标签质量/管线复杂度 |
| "有意思"程度 | 高（曲线漂亮、从零学会） | 更高（中象观感好） | 中（起点太高，曲线不惊艳） |

## 6. 需要你拍板的三件事

1. **"象棋"指哪个？** 中国象棋（需先重写走子，多 1–2 天）还是国际象棋（`python-chess` 直接开工）？
2. **要"看得见的学习曲线"还是"尽量强的棋力"？** 前者走 A/B（从零自博弈），后者走 C（蒸馏+RL）。
3. **这台机器能不能被长期吃满 4 核？** 连续自博弈会占满 CPU 和 1–2 GB 内存，与 Hestia 仿真冲突时需要错峰（或限制到 3 核）。
